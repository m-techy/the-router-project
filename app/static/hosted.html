HOW IT WORKS

One control plane, many free pools.

01

Connect providers

Start the container and add API keys from the browser Setup page. No config file is required for first use.

02

Send a normal OpenAI request

Your apps keep using familiar OpenAI SDKs and point at The Router instead of a single provider.

03

Route by capability + quota

The Router filters by tools, JSON, vision, coding, reasoning and context, then scores available free capacity.

04

Fallback automatically

Rate limits and provider failures trigger cooldowns and pre-response fallback to another eligible provider.

RUN THE ROUTER

Start with Docker. Configure in the browser.

  1. Clone the repository.
  2. Run docker compose up --build.
  3. Open http://localhost:4010.
  4. Use Setup to connect recurring-free providers.
  5. Use the generated SDK snippet in any hobby project.
Python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:4010/v1",
    api_key="local",
)

r = client.chat.completions.create(
    model="free/auto",
    messages=[
        {"role": "user", "content": "Hello"}
    ],
)

print(r.choices[0].message.content)
WHY NOT HOST THE FULL ROUTER HERE?

Vercel is great for the project site; durable routing state needs a database.

FastAPI and streaming can run on Vercel, but this self-hosted version uses a local SQLite quota ledger and local credential store. Vercel Function filesystems are not the durable state layer we want for a multi-provider router. A future hosted mode can use Postgres/Redis or another durable backend, while the free self-hosted platform stays simple.
